# 拾页 · 章节图片采集器

GitHub Pages 网页 + 本机 Node.js 服务。支持章节图片采集，也支持独立将本地图片转为 PDF，以及电脑 / 手机阅读本地作品、批量重命名章节文件夹。

**网页入口：https://moyuhama.github.io/chapter-downloader/**

GitHub Pages 仅托管前端，不能执行 Node.js 或启动 Chromium。使用网页入口时，必须同时在当前电脑启动本机服务；不需要另外租服务器。关闭电脑、本机程序未运行或仅用手机打开网页时，无法执行下载。

## 批量重命名文件夹（1.3.0 及以上助手）

入口：[文件夹改名](https://moyuhama.github.io/chapter-downloader/rename.html)，或首页「文件夹改名」。先选择包含章节目录的父文件夹，点击「预览改名结果」，核对并勾选后再点击「执行批量重命名」。需要更新本机助手。

| 原文件夹名 | 默认新名称 |
| --- | --- |
| `001_第85话-原来你也有遇到` | `85` |
| `002_第86章-标题` | `86` |
| `第087話` | `87` |
| `第８８回` | `88` |
| `第85.50话` | `85.5` |

- 支持话、話、章、回、集、节、節及阿拉伯数字（含全角），去掉编号前导零。未识别名称、中文数字章节、包含多个章节编号的目录默认不勾选，可手动填写新名称后勾选。
- 仅处理直接子文件夹，不递归，不处理符号链接或隐藏目录；内部图片和其他文件名保持不变。只显示本次预览和结果，不提供历史列表。
- 可手动编辑新名称、取消勾选。重复目标、已有同名文件或文件夹都会阻止整批执行；不会自动覆盖、合并或加序号。预览 10 分钟有效，执行前会重新检查目录和目标。
- 普通执行失败会尝试恢复已改名目录；如果外部程序占用了原名称而无法恢复，页面会明确列出仍已改名的目录，保留已有内容供核对。执行时请保持本机助手运行。
- 关联目录正在下载、收尾或转换时不能执行。改名后会同步已保存下载任务、PDF 路径和当前阅读器目录；关联的手机分享会关闭，需要重新开启。

## 图片阅读器（1.2.0 及以上助手）

入口：[阅读器](https://moyuhama.github.io/chapter-downloader/reader.html)，或首页「阅读器」。旧版助手需重新下载最新版 ZIP、解压并打开应用；仅刷新 Pages 不会更新已安装的后台。

- 电脑打开作品目录：自动按自然顺序识别目录内图片和一层章节子文件夹。下载任务也提供「开始阅读」。只保留当前作品，不提供历史列表。
- 默认竖向滚动、图片懒加载，接近章末自动接续下一章（可关闭）。设置里可切换单页翻页和阅读宽度；← → 支持翻页，点击图片收起工具栏。
- 手机图片铺满宽度，章节目录为抽屉。阅读位置按作品在当前浏览器保存，刷新后继续阅读；不同设备、浏览器或分享地址的进度不自动同步。
- 作品路径保存在助手的数据目录，重启后恢复当前作品；原图不修改、不上传。新增下载的章节可用「打开 / 刷新作品」重新读取。

### 手机通过同一 Wi-Fi 阅读

1. 在电脑阅读器打开作品，点击「手机阅读」→「开启手机阅读」。
2. 手机与电脑连接同一个 Wi-Fi，用相机扫描二维码，或打开显示的局域网地址。二维码对应第一个地址；有多个网络时可选择其他地址并复制链接。
3. 手机页面直接由电脑提供，不通过 Pages 连接手机自身的 `127.0.0.1`。电脑须保持开机、联网、助手运行；如果连接失败，检查 Wi-Fi 客户端隔离和电脑的防火墙许可。
4. 点击「关闭手机阅读」、切换作品或退出助手，会立即撤销旧链接。再次开启会生成新链接。共享状态不会在重启后自动恢复。阅读端口默认固定为 `3790`，同一电脑地址和浏览器可保留进度；如端口被占用，可用环境变量 `SHIYE_READER_PORT` 更改。

局域网端口默认关闭，开启后仅提供当前作品的目录和图片，随机令牌随阅读地址提供；无法下载采集、选择电脑目录、执行命令或停止本机服务。请只向需要阅读的人分享此链接，并在可信的本地网络使用；不要配置公网端口转发。SVG/TIFF 会转换为 PNG 后显示。单章最多 5000 张，作品最多 50000 张；PDF 请使用原有 PDF 打开功能。

## 独立图片转 PDF

直接入口：[图片转 PDF](https://moyuhama.github.io/chapter-downloader/#pdf)，或在页面顶部切换「图片转 PDF」。本机运行服务后即可使用，无需输入网址或创建下载任务，也无需启动采集浏览器。

1. 选择直接包含图片的章节文件夹，或输入完整路径后点击「读取图片」。当前入口每次将一个文件夹内的所选图片合成为一个 PDF，不递归读取子目录。
2. 默认按文件名自然排序（例如 `1.png`、`2.png`、`10.png`），可勾选图片、反转顺序或使用 ↑ ↓ 调整顺序。
3. PDF 名称默认采用文件夹名，可以修改；保存位置默认是系统「下载 / Downloads」目录，也可指定其他目录。
4. 点击「生成 PDF」，可查看进度、取消转换，并在完成后打开 PDF 或保存目录。原图不修改、不上传；已有同名文件会使用 `(2)` 等序号避开。
5. 转换与章节 PDF 共享单任务生成队列；如正在生成其他 PDF，会显示等待状态。当前入口不提供历史列表，重启本机服务后需要重新选择图片。

支持 JPEG、PNG、WebP、AVIF、GIF、SVG、TIFF；GIF 使用第一帧。默认启用长图分页，可在生成前取消。损坏或无法转换的图片会报告失败，取消或失败不会留下可误认为完整 PDF 的半成品。

## 使用 GitHub Pages

1. 下载或克隆本仓库，按下文启动本机程序。
2. 打开上方 Pages 网址，点击「启动并连接」。
3. 浏览器如询问本地网络访问权限，按需允许；成功后即可输入网址。部分浏览器可能限制这种连接，可改用 http://127.0.0.1:3789 本机界面。
4. 图片默认保存到系统「下载 / Downloads」目录，也可在开始前选择其他目录；页面只显示当前页面、当前网址明确创建的下载；换网址或重新打开页面时清空列表，不从会话或后台记录恢复旧结果。未结束的其他下载仅显示独立的停止提示。

采集和管理服务只监听 `127.0.0.1`。手机阅读使用手动开启、独立的只读局域网端口。跨域连接只允许 `https://moyuhama.github.io`；如 Fork 后自行发布，启动前通过 `PAGES_ORIGIN=https://你的用户名.github.io npm start` 配置自己的 Pages 来源。不要使用通配符来源，也不要将此服务直接暴露到公网。

GitHub Actions 会在 `main` 分支的 `public/` 改动后发布 Pages。后台代码更新后，需要在本机执行 `git pull`、`npm ci` 并重新启动程序；只刷新 Pages 网页不会更新本机后台。

## 网页启动助手（Mac 预览版）

Pages 顶部提供「启动并连接」「断开并停止服务」。首次点击后检测本机服务；未连接时尝试 `shiye://start`，显示下载、解压和打开安装包的引导，并在首次等待后发起下载。网页不会把“请求下载”误报成“下载完成”，实际下载状态以浏览器下载列表为准。

- Mac 通用包约 500 MB，支持 macOS 14 及以上，包含 Apple 芯片和 Intel 两套运行环境、Node、Chromium 与图片/PDF依赖。无需保留源码项目或安装系统 Node。
- 首次需要用户打开下载的 ZIP 并运行「拾页助手.app」。程序复制到 `~/Applications/拾页助手.app`，注册 `shiye://start`；数据、登录配置和日志位于 `~/Library/Application Support/Shiye`，下载结果仍按用户选择的目录保存。
- 再次使用从网页点击启动即可请求系统唤起，已有同版本服务会复用。浏览器或系统仍可能询问是否打开助手。
- 点击停止会校验当前服务实例、保存下载检查点、取消并清理未完成的 PDF、关闭浏览器并退出；不会停止其他程序。关闭标签页本身不等于停止服务。
- 浏览器没有直接判断本机是否已安装助手的通用能力。超时只显示未连接，页面同时保留重新下载和启动已安装助手入口。已发起过下载后不再自动重复下载。
- **此预览包只有 ad-hoc 签名，尚无 Apple Developer ID 签名和公证，Gatekeeper 可能阻止首次打开。若被拦截请暂用源码方式，不要关闭系统安全保护。正式免拦截分发仍需开发者证书与公证。**
- Windows 暂无启动安装包，仍可按下面的源码方式运行。

源码命令行也支持：`node launcher/cli.mjs start`、`node launcher/cli.mjs stop`、`node launcher/cli.mjs status`。命令行使用固定助手数据目录，与 `npm start` 的项目内数据分开。

构建：`npm run package:mac`；GitHub 的 Build Mac Helper 工作流分别构建并验证两种架构，再合并、验证通用包并发布预览版。包与 SHA-256 校验文件位于 GitHub Releases。发布下载链接只在构建成功后启用。

## 启动

需要 Node.js 20 或更高版本。首次使用：

```sh
git clone https://github.com/moyuhama/chapter-downloader.git
cd chapter-downloader
npm ci
npm run setup
npm start
```

打开 http://127.0.0.1:3789 。也可以双击本目录的 `启动.command`。关闭终端或按 Ctrl+C 停止服务；之后重新启动即可继续中断任务。

## 使用

1. 输入作品目录网址并点击「解析网址」。可点击「试用示例」，用内置 3 章 / 9 张图片验证完整流程。
2. 核对章节列表：可勾选章节、反转顺序。作品文件夹名称默认使用解析出的名称，可在开始下载前修改。保存目录默认是系统「下载 / Downloads」，可点击「选择目录」或输入完整的绝对路径。单章网址请切换页面类型。
3. 点击「预览首个所选章节」，检查图片数量和图片链接。预览只检查第一页，下载时继续读取章内分页。
4. 选择同时下载的章节数（1–4 章，默认 2 章）。「下载完成后生成章节 PDF」默认勾选，原图保留；可选择是否对长条图片自动分页。点击「开始下载」后，并发数、文件夹名称和保存目录即锁定，暂停、重试与继续使用同一位置；启动失败时可继续修改。页面仅显示本次下载，不展示历史任务列表；新任务会替换当前面板。刷新页面可保留本次任务，重启后可恢复未完成任务。进度会定时刷新；暂停在当前请求结束后生效。停止后等待当前操作收尾，再点击继续。
5. 完成后点击「打开文件夹」。有失败项时可重试，已经完成的图片不会重复下载。

如果自动识别不准确，展开「识别设置」：

- 点击「点选章节」，在弹出的 Chromium 浏览器中点击一个章节链接。程序提取同组链接的选择器。
- 点击「点选图片」，在所选章节中点击一张正文图片。程序选择包含多张图片的上级区域。
- 可直接输入 CSS 选择器，例如 `.chapter-list a`、`#reader img`、`a.next-page`。点选是辅助定位，务必重新解析或预览确认范围。
- 可调整最小图片尺寸（默认宽、高都不小于 200px），设为 0 可取消相应限制。
- 自动分页仅识别明确的「下一页」和带 page 参数的 rel=next 链接。对其他布局请指定选择器；程序不跟随已选章节链接或跨域分页。目录自身的分页暂需分别输入。
- 「保存此网站规则」按域名保存设置，下次输入相同站点自动加载。
- 需要登录时点击「打开浏览器 / 登录」，手动登录后返回工具重新解析。同一独立浏览器配置会保留登录状态；不使用你日常浏览器的配置。

## 保存结构

```text
系统下载目录（或你选择的目录）/
└── 作品文件夹名称/
    ├── 001_章节名/
    │   ├── 001.jpg
    │   ├── 002.png
    │   ├── 001_章节名.pdf
│   └── manifest.json
    └── 002_章节名/
        ├── 001.webp
        └── manifest.json
```

章节按照确认后的列表顺序编号，图片按照正文 DOM 顺序和分页顺序编号，编号与下载完成先后无关。图片格式按响应类型保留，不强制转成 JPG。每张图最多尝试三次，每章同时下载 3 张图片；章节采用并发队列，默认同时处理 2 章，可在开始前选择 1–4 章。章节文件夹和图片编号在处理前确定，与完成先后无关。旧版本已保存的任务继续按原来的单章顺序处理。暂停、停止和继续作用于全部并发章节，停止后需等待正在进行的请求收尾才能开始新任务。

macOS 与 Windows 支持系统目录选择窗口，Linux 使用 zenity；无法打开选择窗口时可直接输入完整的目录路径。默认路径为当前用户主目录下的 `Downloads`；如果系统下载目录被手动迁移，请选择实际目录。

任务检查点存放在 `data/jobs.json`，站点规则在 `data/rules.json`，独立浏览器配置在 `data/browser/`。这些运行数据和下载文件已加入 `.gitignore`。只在本机监听，不需要上传网址、图片或登录信息到云端。请不要把包含登录状态的 `data/` 目录分享给别人。

## 章节 PDF

每章图片齐全后，在对应章节目录生成同名 PDF（如 `001_第一章/001_第一章.pdf`）。图片按下载清单中的编号排序；普通图片对应一页，页面按图片比例适配，不添加边框或页眉。原始图片继续保留。

- PDF 默认启用，可在开始前取消勾选；启动后该选项与长图分页选项一起锁定。旧版本任务继续沿用原有的仅下载图片行为。
- 长图自动分页默认启用：高宽比大于 3 的图片按约 2:3 的页面比例连续切分。切分可能经过文字或画面，可取消勾选以保留一张长图一页。
- JPEG、PNG 原图尽量直接嵌入；WebP、AVIF、SVG 等格式转成 PNG 后嵌入，GIF 使用第一帧。原文件不会修改。不支持或损坏的图片会标记 PDF 失败。
- 图片下载可并发进行，PDF 独立排队，每次只生成一章。网页显示 PDF 排队、生成、已完成或失败状态；章节列表提供打开 PDF 的入口。
- 缺图的章节不会生成 PDF。补齐图片后自动生成；仅 PDF 出错时，可点击「重试 PDF」，不重新下载图片。
- 暂停在当前图片处理完后生效；停止会清理正在生成的临时 PDF。只有正式写入成功的文件才会显示已完成，继续任务可重新生成未完成的 PDF。
- 本机程序新增 `pdfkit` 和 `sharp` 依赖，更新后运行 `npm ci` 并重启，或双击「启动.command」自动检查和安装缺失依赖。

## 适配范围

支持常见 HTML 图片、懒加载、图片 srcset、内嵌 data 图片和可在页面读取的 blob 图片。自动识别是启发式规则，不能保证覆盖任意网站。目录需先确认，复杂网站可能需要调整选择器；Canvas 拼图、加密图片、CSS 背景图片、iframe 阅读器与无限滚动虚拟列表不保证支持。不会自动绕过验证码或付费访问。

单页最多滚动 120 次、单章最多读取 100 页；超过分页上限会报告失败。任务内会去掉重复的图片 URL。链接相同但内容随请求变化的站点需要专门适配。每个新任务创建独立作品文件夹，同名目录已存在时自动使用「作品名 (2)」等名称，不覆盖原有文件。继续或重试已有任务仍使用原目录。旧版本任务继续使用它们原来记录的保存路径。
