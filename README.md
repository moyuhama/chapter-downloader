# 拾页 · 章节图片采集器

GitHub Pages 网页 + 本机 Node.js / Playwright 下载服务。输入章节目录网址，核对章节和图片，再按阅读顺序下载到本机。

**网页入口：https://moyuhama.github.io/chapter-downloader/**

GitHub Pages 仅托管前端，不能执行 Node.js 或启动 Chromium。使用网页入口时，必须同时在当前电脑启动本机服务；不需要另外租服务器。关闭电脑、本机程序未运行或仅用手机打开网页时，无法执行下载。

## 使用 GitHub Pages

1. 下载或克隆本仓库，按下文启动本机程序。
2. 打开上方 Pages 网址，点击「连接本机服务」。
3. 浏览器如询问本地网络访问权限，按需允许；成功后即可输入网址。部分浏览器可能限制这种连接，可改用 http://127.0.0.1:3789 本机界面。
4. 图片默认保存到系统「下载 / Downloads」目录，也可在开始前选择其他目录；页面只显示本次下载。

本机服务只监听 `127.0.0.1`。跨域连接只允许 `https://moyuhama.github.io`；如 Fork 后自行发布，启动前通过 `PAGES_ORIGIN=https://你的用户名.github.io npm start` 配置自己的 Pages 来源。不要使用通配符来源，也不要将此服务直接暴露到公网。

GitHub Actions 会在 `main` 分支的 `public/` 改动后发布 Pages。后台代码更新后，需要在本机执行 `git pull`、`npm ci` 并重新启动程序；只刷新 Pages 网页不会更新本机后台。

## 启动

需要 Node.js 20 或更高版本。首次使用：

```sh
git clone https://github.com/moyuhama/chapter-downloader.git
cd chapter-downloader
npm ci
npm run setup
npm start
```

打开 http://127.0.0.1:3789 。也可以双击本目录的 `启动.command`。关闭终端或按 Ctrl+C 停止服务；之后重新启动即可继续中断任务。

## 使用

1. 输入作品目录网址并点击「解析网址」。可点击「试用示例」，用内置 3 章 / 9 张图片验证完整流程。
2. 核对章节列表：可勾选章节、反转顺序。作品文件夹名称默认使用解析出的名称，可在开始下载前修改。保存目录默认是系统「下载 / Downloads」，可点击「选择目录」或输入完整的绝对路径。单章网址请切换页面类型。
3. 点击「预览首个所选章节」，检查图片数量和图片链接。预览只检查第一页，下载时继续读取章内分页。
4. 点击「开始下载」后，文件夹名称和保存目录即锁定，暂停、重试与继续使用同一位置；启动失败时可继续修改。页面仅显示本次下载，不展示历史任务列表；新任务会替换当前面板。刷新页面可保留本次任务，重启后可恢复未完成任务。进度会定时刷新；暂停在当前请求结束后生效。停止后等待当前操作收尾，再点击继续。
5. 完成后点击「打开文件夹」。有失败项时可重试，已经完成的图片不会重复下载。

如果自动识别不准确，展开「识别设置」：

- 点击「点选章节」，在弹出的 Chromium 浏览器中点击一个章节链接。程序提取同组链接的选择器。
- 点击「点选图片」，在所选章节中点击一张正文图片。程序选择包含多张图片的上级区域。
- 可直接输入 CSS 选择器，例如 `.chapter-list a`、`#reader img`、`a.next-page`。点选是辅助定位，务必重新解析或预览确认范围。
- 可调整最小图片尺寸（默认宽、高都不小于 200px），设为 0 可取消相应限制。
- 自动分页仅识别明确的「下一页」和带 page 参数的 rel=next 链接。对其他布局请指定选择器；程序不跟随已选章节链接或跨域分页。目录自身的分页暂需分别输入。
- 「保存此网站规则」按域名保存设置，下次输入相同站点自动加载。
- 需要登录时点击「打开浏览器 / 登录」，手动登录后返回工具重新解析。同一独立浏览器配置会保留登录状态；不使用你日常浏览器的配置。

## 保存结构

```text
系统下载目录（或你选择的目录）/
└── 作品文件夹名称/
    ├── 001_章节名/
    │   ├── 001.jpg
    │   ├── 002.png
    │   └── manifest.json
    └── 002_章节名/
        ├── 001.webp
        └── manifest.json
```

章节按照确认后的列表顺序编号，图片按照正文 DOM 顺序和分页顺序编号，编号与下载完成先后无关。图片格式按响应类型保留，不强制转成 JPG。每张图最多尝试三次，每章三个并发下载；所有章节顺序处理。

macOS 与 Windows 支持系统目录选择窗口，Linux 使用 zenity；无法打开选择窗口时可直接输入完整的目录路径。默认路径为当前用户主目录下的 `Downloads`；如果系统下载目录被手动迁移，请选择实际目录。

任务检查点存放在 `data/jobs.json`，站点规则在 `data/rules.json`，独立浏览器配置在 `data/browser/`。这些运行数据和下载文件已加入 `.gitignore`。只在本机监听，不需要上传网址、图片或登录信息到云端。请不要把包含登录状态的 `data/` 目录分享给别人。

## 适配范围

支持常见 HTML 图片、懒加载、图片 srcset、内嵌 data 图片和可在页面读取的 blob 图片。自动识别是启发式规则，不能保证覆盖任意网站。目录需先确认，复杂网站可能需要调整选择器；Canvas 拼图、加密图片、CSS 背景图片、iframe 阅读器与无限滚动虚拟列表不保证支持。不会自动绕过验证码或付费访问。

单页最多滚动 120 次、单章最多读取 100 页；超过分页上限会报告失败。任务内会去掉重复的图片 URL。链接相同但内容随请求变化的站点需要专门适配。每个新任务创建独立作品文件夹，同名目录已存在时自动使用「作品名 (2)」等名称，不覆盖原有文件。继续或重试已有任务仍使用原目录。旧版本任务继续使用它们原来记录的保存路径。

